# Alerts implementation plan

> Use superpowers:executing-plans inline under the user's existing continuous
> execution authorization. One independent whole-branch review remains required
> before release; no implementer delegation is needed.

**Goal:** Trader-created alerts with explicit timing, numeric/drawing/study
anchors, lifecycle, persistence and usable widget and OpenAlgo interfaces.

**Architecture:** Headless base controller, structural drawing provider, existing
PriceLine visuals and chart state/event bus; DOM stays in hosts and widget.

**Tech stack:** TypeScript, Vitest, Playwright, current package tiers. No new
runtime dependencies.

**Spec:** `../specs/2026-09-20-alerts-design.md`, implementing Part 2 of
`../specs/2026-09-20-open-interest-and-alerts-requirements.md`.

## Global constraints

- Keep original main checkouts and the user's eight OI edits untouched.
- No comparison brands, emojis or em/en dashes in additions.
- Preserve IndicatorAlertSpec and its existing indicator:alert behavior.
- No historical delivery on attach, reset, prepend, restore or replay.
- Default policy onBarClose; intrabar observations can later disappear.
- No automatic orders or delivery transport. Browser order routes are mocked.
- Measure bundle costs deliberately and update API/skills and final release facts.
- Chart persistence uses the existing restoreState API, not a new setState alias.

## Review focus

1. A trigger listener removes/disables another alert, throws or destroys the
   chart. State must already be consumed and later records must not fire stale.
2. History replacement preserves the tail time but changes its extrema. It is
   still history, not a new live observation.
3. Two identical studies restore with distinct anchors; a template replacement
   cannot silently retarget an alert to the first matching descriptor.
4. An idle market passes expiry or the wall clock moves backwards. No stale
   trigger or runaway timer is acceptable.
5. A line crosses a session gap or a log-price pane. Alert geometry must match
   the plotted shape, not a different raw-time interpolation.

## Pre-flight rulings

- User-provided spec plus explicit continuous implementation authorization
  supplies the design brief; routine interface choices are resolved here without
  another approval round. This preserves the user's requested execution method.
- Existing indicator alerts evaluate newly appended timestamps rather than an
  explicit close signal. Keep that compatibility behavior; the new controller
  implements onBarClose independently instead of claiming the old hook does it.
- A runtime optional document slot avoids importing the controller into Chart.
  Widget/hosts must attach it explicitly, just as they attach DrawingController.
- Task 1 produces the source event consumed by Tasks 2 and 3. Task 3 produces
  drawing resolution consumed by Task 4. Task 4 orders restoration consumed by
  Tasks 5 and 6. Tasks 2 and 4 preserve instance identity, not descriptor identity.

## Task 1 checkpoint

Implemented the structural headless price controller and primary-source update
bridge. Price alerts do not flush indicators or copy whole history per tick.
History/live distinction, arm-time snapshots, monotonic judged-bar watermarks,
context/replay/host pause, cooldown, one idle-expiry timer and reentrant teardown
are exercised by 26 real-chart tests. Source updates from secondary series do
not masquerade as primary updates, including when their global axis runs ahead.

Evidence: initial 19 tests RED without the controller; 19 GREEN after the first
implementation. Two history rollback regressions reproduced duplicate delivery,
then passed with monotonic watermarks. A lifecycle regression caught the wrong
creation event name and passed with the required alert:created event. Full suite
5409 tests in 224 files passed; example suite 235 tests in 18 files passed; lint,
typecheck, build and all 8 declaration checks passed. API generation with warnings
as errors and skill coverage 908/908 passed. Logs are under artifacts/candidate/
alerts-task1-*; RED logs also include alerts-controller-red, alerts-watermark-red
and alerts-events-red.

Ruling: the Chart event bus already swallows listener exceptions. Preserve this
contract and assert once-state remains consumed when delivery throws, rather
than changing event propagation. Cost if wrong: hosts must log their own delivery
failures, as before. Assertions inside these callbacks were moved outside the
bus so swallowed assertion errors cannot make a test pass vacuously.

Ruling: allow the measured feature cost in explicit bundle budgets. Base 79.00
to 80.69 kB, base plus trade 88.30 kB, widget terminal 187.75 kB, all tiers
226.23 kB. New limits are respectively 81, 88.5, 188 and 226.5 kB; unaffected
tier limits stay unchanged. The chart-only bridge grows 50.25 to 50.29 KiB,
with a 50.30 KiB cap and a new assertion that AlertController is absent. All
size/shake checks passed after recording these intentional allowances. Cost if
wrong: exported base consumers download about 1.69 kB more compressed code;
chart-only consumers pay about 0.04 KiB. Final release facts remain a later gate.

## Task 4 checkpoint

Added version-1 alert documents, detached serialization, legacy bare-list
migration and validation before mutation. Chart state carries alert documents
with or without an evaluator. The controller hydrates on attachment, persists
lifecycle changes before delivery callbacks and keeps closed/touched bar guards
through reload, including cooldown-suppressed touches. Runtime payload identity
is preserved until serialization, where unsupported JSON values reject explicitly.

Chart restore preserves specific study identities and reserves all restored IDs
before generating any missing legacy IDs. Reusable templates strip identity.
The drawing controller handles drawings:restore before alerts:restore validates
anchors; the widget's redundant manual drawing restores were removed. Missing
restored drawing/study/plot anchors emit removal reasons. Confirmed once alerts
remain triggered and visible; historical loading, attachment and restore stay
silent. Temporary inventory changes during restore cannot evaluate or reconcile
alerts prematurely.

Evidence: the initial persistence run failed 20 tests against the missing API.
Further RED regressions covered array accessors, explicit null settings, opaque
payload fields that workspace parsing would lose, and preservation of the
WorkspaceDocumentError contract. Thirty persistence tests now pass; the full
library suite passes 5486 tests in 227 files. Reference-host tests pass 235/235.
Nine alert browser cases pass across Chromium, Firefox and WebKit, including
an actual page reload with two triggered once alerts and all five visible levels.
Restored screenshots were inspected in each engine; no duplicate overlays or
deliveries appeared. Typecheck, lint, build, eight declaration checks, API with
warnings as errors, and skills coverage 913/913 pass. Logs use alerts-task4-*,
alerts-state-*, alerts-payload-* and alerts-workspace-error-* names.

Ruling: the core imports the shared alert document parser, not the controller.
This lets a chart without an evaluator validate and round-trip saved alerts
atomically. Cost if wrong: chart-only users pay the parser's compressed cost;
the evaluator, registry, drawing tier and widget still tree-shake away. Measured
chart-only 50.26 to 51.82 KiB, with a deliberate 51.90 KiB cap. Base is 84.14 kB,
base plus trade 91.75 kB, widget terminal 192.03 kB and aggregate 230.77 kB,
capped at 84.5, 92, 192.5 and 231 kB. Workspace is 5.28 kB under its existing
6 kB limit. Unaffected tier limits stay unchanged.

Ruling: portable workspace privacy rules still apply to opaque routing payloads,
but encountering a reserved field now rejects that payload instead of silently
stripping a field. Symbols, hidden properties and extra array properties also
reject rather than disappear. Cost if wrong: a host must keep private routing
information outside the portable document and resolve it from a nonprivate key.
Standalone alert documents remain opaque finite JSON without workspace-specific
account-field filtering.

Ruling: an absent alert document in a restored legacy chart clears the current
controller, while an absent drawing provider retains drawing alerts as unavailable.
An actual missing drawing in an attached provider drops its alert with a reason.
Cost if wrong: hosts that used partial chart restores must include alert state
when they intend to retain it. Template application must create fresh study
identities and explicitly retain any unrelated alerts it intends to keep.
